# 直播字幕校对台（Live Caption Desk）

一个纯前端、可确定性重放的直播字幕校对工作台。模拟现场字幕在**网络抖动**下乱序、重复、晚到，以及机器修订与人工锁定发生冲突的完整处置流程。数据全部保存在浏览器内存中，不依赖任何后端服务。

技术栈：**React 18 + TypeScript + Vite**，测试使用 **Vitest + Testing Library**。

## 运行方式

```bash
npm install        # 安装依赖
npm run dev        # 启动开发服务器（默认 http://localhost:5173）
npm test           # 运行全部自动化测试（一次性）
npm run test:watch # 测试监听模式
npm run build      # 类型检查 + 生产构建，产物在 dist/
npm run preview    # 本地预览生产构建
```

要求 Node.js 18+。

## 界面与功能

工作台分三个区域，同屏可见：

- **直播预览**：当前真正播出的字幕。遵循“不得越过缺口播出”的直播规则——102 未到时，即使 103 已收到，播出线也停在 101，并明确提示在 #102 处等待。
- **字幕时间线**：字幕按序号 101–103 排列。缺失序号渲染为带斜纹底、虚线框、⚠ 图标的**明显空位**；晚到片段补回后带“晚到补回”标记。每条字幕可直接“修改”并“锁定”。
- **事件流**：入库、缺口打开/补齐、重复丢弃、修订应用、冲突挂起/裁决、人工编辑/锁定，全程留痕，最新在上。

顶部统计条一眼可辨：当前播出、缺口数、重复事件数、待处理冲突数、已锁定数、到位/预期数。

### 核心规则

| 情况 | 行为 |
| --- | --- |
| 乱序到达 | 按序号归位，不按到达顺序排列；中间序号形成缺口空位 |
| 晚到片段 | 自动补回对应空位，标记“晚到补回”，并记录“缺口补齐”事件 |
| 重复事件 | 传输层 `eventId` 幂等去重，**绝不生成第二条字幕**，仅计数并留痕 |
| 机器修订（未锁定） | 版本号更高则自动应用；过期版本丢弃 |
| 机器修订（已人工锁定） | **绝不静默覆盖**：弹出冲突对话框，并排列出人工版与机器版，由运营选择“保留人工版本”或“接受机器新版本” |
| 重放 | 先整体 reset 到空状态，再从 T+0 开始，无任何残留 |

### 可访问性：不只靠颜色

所有状态都同时用**文字 + 图标 + 形状/纹理**表达：缺口为斜纹底 + 虚线框 + “缺口/缺失片段”文字与 ⚠ 图标；锁定为 🔒 图标 + “人工锁定”文字 + 紫色实左边框；播出行为 ▶ 图标 + “播出”标签 + 红色左边框；重复为红色左边框 + “重复丢弃”文字标签。弹窗使用 `alertdialog`/`aria-modal`，直播画面使用 `aria-live` 播报。

## 内置“网络抖动”场景

场景在 `src/engine/scenario.ts` 中**静态写死，不含任何随机数或网络调用**：

| 场景时间 | 事件 | eventId | 说明 |
| --- | --- | --- | --- |
| T+0.0s | 101 初稿 | `evt-101` | 正常到达并播出 |
| T+0.9s | 103 初稿 | `evt-103` | 乱序：#102 形成缺口 |
| T+1.7s | 103 重传 | `evt-103`（相同） | 重复事件，必须丢弃 |
| T+2.5s | 102 初稿 | `evt-102` | 晚到，自动补位 |
| T+3.4s | 102 机器修订 v2 | `evt-102-rev2` | 若 #102 已锁定则产生冲突 |

### 播放控制

- **暂停 / 继续**：随时暂停，在 T+2.5s 到 T+3.4s 之间手动编辑并锁定 102，再继续即可看到冲突。
- **单步**：暂停状态下精确投递且仅投递下一个事件（测试也用它驱动，无计时器竞态）。
- **倍速**：0.5× / 1× / 2× / 4×，切换时以当前虚拟时刻为基准，不跳变、不丢事件。
- **重放**：清空所有字幕、去重表、冲突、事件流与计数器，回到干净的 T+0 暂停态。

### 确定性保证

- 所有业务逻辑集中在纯函数 reducer（`src/engine/reducer.ts`）中：相同输入状态 + 相同动作序列，必然得到逐字段相同的输出状态。
- 播放器只让墙钟驱动一个**虚拟时钟**，事件按 `arriveAtMs` 投递；墙钟快慢（暂停/倍速）只影响观感，不影响事件的顺序、内容与恰好一次的语义（重复事件的去重仍由 reducer 保证）。
- 冲突 ID 由 `序号 + 版本号` 派生，日志按计数器编号，不使用 `Date.now()`/`Math.random()`。
- “重放”先 dispatch `reset`（状态与 `createInitialState()` 深比较相等），再从第 0 个事件开始，因此**每次重放都从干净状态开始，相同操作得到相同结果**。

## 目录结构

```
src/
├── types.ts                  # 领域模型与 Action 定义
├── App.tsx                   # 工作台组装
├── engine/
│   ├── scenario.ts           # 静态网络抖动脚本（唯一“数据源”）

├── components/               # TransportBar / LivePreview / Timeline / EventLog / ConflictPanel / StatsBar
└── **/*.test.ts(x)           # 纯引擎单测 + 应用级集成测试
```

## 自动化测试覆盖

`npm test` 共 15 个用例（Vitest + Testing Library）：

- **乱序补齐**：103 先到时 #102 留缺口且播出线不越过缺口；晚到 102 自动补位、推进播出线。
- **重复去重**：相同 eventId 不产生第二条字幕、仅计数留痕；同一事件投递任意次与一次结果一致（幂等）。
- **版本更新**：未锁定时机器修订自动应用；过期版本丢弃。
- **锁定冲突**：锁定后修订不覆盖文本而挂起冲突；分别验证“保留人工版”和“接受机器版”两条裁决路径。
- **无残留重放**：reset 与初始状态深相等；两轮相同操作序列状态逐字段一致；重放后缺口/重复/冲突/锁定统计全部归零。
